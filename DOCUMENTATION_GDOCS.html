1. Product Overview

1.1 What is DecayState?

DecayState is a gamified personal accountability web application that uses an AI mentor (the "Switch Protocol") to help users define goals, execute daily tasks ("mandates"), and track their progress through a journal system — all wrapped in a cyberpunk/military HUD-inspired interface.

The central metaphor is "decay": if you don't act on your goals, your Integrity Score drops and your future self "decays." The visual feedback loop — showing a decay probability in real-time — creates urgency and gamification around daily accountability.

1.2 Problem Statement

Most productivity tools are either:

  • Too passive — plain to-do lists with no consequence for inaction
  • Too generic — no personalization, no AI-driven insights
  • Not sticky — no gamification, no emotional engagement

DecayState addresses this with: (1) visualizing consequences via integrity scores, (2) an AI-powered mentor that modifies your data, (3) structured daily reflection via journals, and (4) a cyberpunk HUD aesthetic that makes productivity feel like a mission.

5. Core Features

5.1 Missions (Goals)

The foundational entity — a user's overarching objective.

FieldPurpose
goalWhat the user wants to achieve
manifestoDetailed plan/strategy
timeframeDuration (e.g., "30 Days", "6 Months")
is_activeOnly one active at a time
image_urlOptional uploaded image via Supabase Storage
Created during onboarding or via MissionSelector modal. upsertActiveMission() updates if exists, otherwise creates new and deactivates others. AI agent can also update via update_mission tool.

5.2 Mandates (Tasks / Directives)

Daily actionable tasks, optionally linked to a mission.

FieldPurpose
labelShort task description
categoryphysical intellectual spiritual
rationaleWhy this task matters (often AI-generated)
completedBoolean completion status
mission_idFK to active mission (nullable)

Key behaviors: Completion rate = Integrity Score. Observer limit: 5 mandates. "Verify Compliance" has a 1.5s scanning animation. AI can create/complete/delete/edit mandates via tools.

5.3 Journal (Protocol Log)

Daily reflection entries with wins, failures, and adjustments.

Key behaviors: Split-view UI (form left, timeline right). Image upload via Supabase Storage. Can link to missions and mandates. Observer limit: 10 entries. AI can create entries via create_journal_entry tool.

5.4 Neural Link (AI Chat)

An AI agent powered by LangGraph that can reason, call tools, and modify user data in real-time.

Available Tools (10 total)

ToolTypePurpose
get_user_contextReadFetches mission, mandates, journal, and integrity
get_upcoming_tasksReadLists mandates with optional filter
break_down_taskReadDecomposes complex goals into sub-tasks (suggestions only)
search_journalReadSearches journal entries by keyword
create_mandateWriteCreates a single mandate
toggle_mandateWriteMarks mandate as completed/uncompleted
delete_mandateWritePermanently deletes a mandate
edit_mandateWriteUpdates a mandate's label
update_missionWriteCreates or updates the active mission
create_journal_entryWriteCreates a journal entry

5.5 Activity Log (Live System Terminal)

Real-time event feed displayed in the Command Center.

  • Dual-write: Events go to Supabase DB + localStorage (zero-latency local display)
  • Tier-gated history: Observer = 24 hours, Operator = 1 year
  • Event types: mandate, journal, mission, ai, system
  • Polling: localStorage checked every 2s for new events

7.3 Row Level Security

All tables have RLS enabled. Policy: users can only access their own data (auth.uid() = user_id). Subscriptions are SELECT-only for users. Service role client (used in webhooks) bypasses RLS.

7.4 Auto-Updated Timestamps

A trigger function update_updated_at() fires BEFORE UPDATE on all tables with an updated_at column, automatically setting it to now().

10.2 Middleware (Session Proxy)

middleware.ts runs on every request and calls updateSession():

  1. Creates server-side Supabase client
  2. Calls getClaims() — validates JWT signature (more secure than getSession())
  3. If unauthenticated + non-public route → redirect to /login
  4. Public routes: /, /login, /signup, /auth/*, /api/*, /pricing

11.3 Checkout Flow

  1. User clicks "Upgrade" → Frontend POSTs to /api/dodo/create-checkout
  2. Server creates Dodo checkout session with product ID + metadata: { user_id }
  3. Returns { checkout_url } → Frontend redirects to Dodo
  4. After payment, Dodo sends webhook to /api/dodo/webhook
  5. Webhook upserts subscription (tier: "operator", status: "active")

12. Getting Started

12.1 Prerequisites

  • Node.js 18+
  • npm or equivalent package manager
  • Supabase project (free tier works)
  • Groq API key (console.groq.com)
  • Dodo Payments account (optional, for payments)

12.2 Environment Setup

Copy .env.example to .env.local and fill in:

# AI / LLM
GROQ_API_KEY=gsk_...
GROQ_MODEL_ID=llama-3.3-70b-instant

# Supabase
NEXT_PUBLIC_SUPABASE_URL=https://xxx.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=eyJ...
SUPABASE_SERVICE_ROLE_KEY=eyJ...

# Dodo Payments (optional)
DODO_API_KEY=...
DODO_WEBHOOK_SECRET=...
NEXT_PUBLIC_DODO_OPERATOR_PRODUCT_ID=...
NEXT_PUBLIC_DODO_OPERATOR_ANNUAL_PRODUCT_ID=...

# App
NEXT_PUBLIC_APP_URL=http://localhost:3000

12.3 Database Setup

Run the SQL schema from planning.md in the Supabase SQL Editor. Creates all 8 tables, RLS policies, and triggers.

12.4 Storage Buckets

Create these buckets in Supabase Storage:

  1. avatars (public)
  2. mission-images (private)
  3. journal-images (public)

12.5 Run Locally

npm install
npm run dev

Open http://localhost:3000
